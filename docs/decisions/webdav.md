# Architecture Decision Record: Read-Only WebDAV (`/webdav/`) & M3U Bridge (`/webdav.m3u`)

## Status
Accepted & Implemented

## Context
Media Vault stores media across local mounted drives (`STORAGE_MODE=drives`), single-part Telegram MTProto messages, and >2 GB multi-part Telegram messages (`media_parts`), all indexed in SQLite (`media_items`). External native players and OS file managers—VLC, Infuse, Kodi, MPV, Nova Video Player, macOS Finder, Windows Explorer, Android file managers, and `rclone`—speak RFC 4918 WebDAV with HTTP Basic Auth and HTTP `Range` seeking rather than Media Vault's custom JSON/Bearer REST API.

## Key Architectural Decisions
1. **Pure-Stdlib RFC 4918 Implementation (`app/webdav.py` + `app/routers/webdav.py`):**
   - Zero third-party WebDAV libraries (e.g. `wsgidav` avoided to keep the ASGI async streaming pipeline and zero-copy `iter_source_range()` intact).
   - Pure-stdlib `xml.etree.ElementTree` XML generation and parsing with bounded streaming body reads (64 KiB cap) and DTD/`<!ENTITY` rejection.
2. **Canonical 1:1 Folder Tree at `/webdav/` + Sibling `/webdav.m3u`:**
   - `/webdav/` mirrors Media Vault's real folder tree directly (including nested folders such as `Movies/Sci-Fi` with auto-synthesized intermediate parent collections and case-insensitive folder merging matching `Database.list_folders()`).
   - Virtual duplicate views (`_By Type/`, `_By Tag/`, `_Recent/`) were deliberately omitted from `/webdav/` because Infuse, Kodi, Nova Video Player, and `rclone copy/sync` recursively traverse the share root and would index or download every file 3–4× if virtual views lived inside `/webdav/`.
   - A sibling `GET/HEAD /webdav.m3u` playlist endpoint (with `?folder=`, `?media_type=`, `?tag=` filters) provides quick sequential playback for VLC/MPV/Kodi without polluting `PROPFIND /webdav/`.
3. **Fail-Closed HTTP Basic Auth Defaults:**
   - Settings: `WEBDAV_ENABLED=true`, `WEBDAV_USERNAME=vault`, `WEBDAV_PASSWORD=`, `WEBDAV_ALLOW_ANONYMOUS=false`.
   - Resolution priority: `WEBDAV_PASSWORD` → `WEB_AUTH_TOKEN` → explicit `WEBDAV_ALLOW_ANONYMOUS=true` opt-in → fail-closed `401 Unauthorized` (`unconfigured`). A configured password/token can never be bypassed by `WEBDAV_ALLOW_ANONYMOUS=true`.
   - Constant-time `hmac.compare_digest` on both username and password without short-circuiting.
4. **Zero-MTProto Metadata Invariant:**
   - `PROPFIND` (`Depth: 0`/`1`, `Depth: infinity` rejected with `403` + `<D:propfind-finite-depth/>`), `OPTIONS`, `HEAD`, `GET /webdav.m3u`, and conditional `304 Not Modified` responses perform pure SQLite metadata queries and trigger **0** `tg_pool.prepare_stream()` calls.
   - `GET` reuses `resolve_media_source()`, `_parse_range_header()`, `prefetch_multipart_first()`, and `iter_source_range()` (updated to forward `total_size` via `_call_iter_telegram_range`) for full `200`/`206`/`416` seeking + `If-Range` / `If-None-Match` support.
5. **Deterministic Collision-Free Virtual Naming:**
   - Within each folder, items sharing a casefolded filename (or colliding with a child folder name) are deterministically decorated with ` [<media_id>]` before the file extension (with dotfile handling and secondary collision guards), ensuring 1:1 round-trip resolution from `PROPFIND` and `/webdav.m3u` to `GET`/`HEAD`.
